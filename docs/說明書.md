# 本機照片整理說明書

把未整理的 RAW / JPEG 在本機分成保留、覆核、廢片。原檔不刪、不改、不搬移。結果資料夾只建立硬連結。

程式是**同一套原始碼**，用作業系統適配層分開 Windows 與 Linux 的介面差異。整理流程、分數、分桶規則兩邊相同。

---

## 1. 概念

### 1.1 為什麼用硬連結

`keep`、`review`、`reject` 裡的檔名，和原始資料夾裡的照片是**同一份資料的兩個名稱**。

- 不會多佔一份磁碟空間。
- 刪掉結果資料夾裡的檔名，原檔還在。
- 兩邊都刪掉，照片才真正消失。
- 硬連結只能建在**同一個磁碟、同一個支援硬連結的檔案系統**上。

| 系統 | 可用 | 不可用 |
| --- | --- | --- |
| Windows | NTFS、ReFS | exFAT、FAT32 |
| Linux | ext4、XFS、Btrfs、ZFS | exFAT、FAT、vfat |

### 1.2 三種結果代表什麼

| 結果 | 意思 |
| --- | --- |
| 保留 `keep` | 建議留下。連拍代表，或散張裡又清楚、美學分也高的 |
| 覆核 `review` | 程式拿不定，請人看。夜景、淺景深、美學居中常在這裡 |
| 廢片 `reject/...` | 建議不用。再細分成失焦、美學偏低、缺陷、完全重複、近重複、連拍落選 |

### 1.3 兩種照片怎麼分

- **連拍**：同一機身、時間接近（預設 2 秒內）、畫面也接近。只在這一簇裡比，留下一張代表。
- **散張**：間隔較長、畫面不像的單張。用絕對清晰度、絕對美學分、本批散張百分位分好壞。**不用**簇內百分位。

### 1.4 四種可自選篩選

| 篩選 | 作用 |
| --- | --- |
| 清晰度 | 失焦地板、技術過關線 |
| 連拍與重複 | 完全相同只留一張；連拍只留代表 |
| 美學分 | CLIP 給約 1～10 分 |
| 視覺語意 | 本地 VLM 看閉眼等缺陷。視窗預設只看「準備留下的」與連拍分數矛盾的少數張 |

至少要留一種篩選才能開始。

## 2. 架構

```
原始照片資料夾
      │
      ▼
【第零階段：盤點與配對】列檔、EXIF、RAW+JPEG 成對
      │
      ▼
【第一階段：CPU 快篩】內嵌預覽、雜湊去重、清晰度
      │
      ▼
【第二階段：GPU】CLIP 美學分 → 釋放 → Ollama / vLLM 視覺語意
      │
      ▼
【第三階段：分級】連拍選代表 / 散張絕對分級 → 硬連結 → SQLite
```

## 3. 外部資源怎麼掛接

程式**不會**改系統登錄檔，也**不會**把模型嵌進 `.exe`。它只在執行時自動找本機已裝好的東西。掛接方式如下。

```
顯示卡驅動 ──► CUDA Runtime ──► PyTorch（pip）──► 美學分（CLIP）
                                                    │
                                                    ▼ 跑完釋放顯存
Ollama 服務（本機 :11434）──► HTTP ──► 視覺語意（qwen2.5vl）
ExifTool（PATH）──► 子行程 ──► RAW 時間與內嵌預覽
美學權重 .pth（檔案）──► 直接讀取
```

開視窗時上方檢查列會顯示是否就緒。缺了大多是**警告**，不會擋住整批：對應功能會略過，其餘仍會跑完。

### 3.1 顯示卡驅動與 CUDA（給美學分用）

| 層級 | 誰負責 | 程式怎麼用 |
| --- | --- | --- |
| NVIDIA 驅動 | 你在系統安裝（GeForce / Studio） | 不直接呼叫 |
| CUDA | 隨 **CUDA 版 PyTorch** 一起裝即可；多數情況不必另裝完整 CUDA Toolkit | `torch.cuda.is_available()` |
| PyTorch + open_clip | 虛擬環境 `pip install -e ".[gpu]"`，再依官網補對的 CUDA wheel | 載入 CLIP，在 GPU 打分 |

**建議檢查順序（Windows / Linux 相同）：**

1. 裝置管理員或 `nvidia-smi` 看得到顯卡、驅動正常。
2. 虛擬環境裡執行：

```powershell
python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'no-cuda')"
```

3. 若 `False`：到 [PyTorch 官網](https://pytorch.org/get-started/locally/) 選你的系統與 CUDA 版本，**重裝** `torch`（不要只裝 CPU 版），再確認 `open_clip_torch` 仍在。
4. 視窗「顯示卡」檢查應變綠；開始整理且勾了「美學分」時才會真正載入模型。

沒有 CUDA 時程式會**自動改走 CPU** 算美學分（很慢），或你關掉「美學分」篩選。

### 3.2 美學權重與 CLIP 下載

| 資源 | 放哪裡 | 掛接 |
| --- | --- | --- |
| 線性頭 `sac+logos+ava1-l14-linearMSE.pth` | 專案 `models/` 目錄 | 自動尋找；也可用環境變數 `PHOTOCULL_AESTHETIC_WEIGHTS` 或 `--aesthetic-weights` |
| CLIP 影像編碼器 `ViT-L-14` | Hugging Face 快取（第一次下載約數 GB） | `open_clip` 自動下載；建議設 `HF_HUB_DISABLE_XET=1`（啟動腳本已帶） |

權重找不到 → 美學分略過；散張除明顯失焦外先進覆核。連拍仍可用清晰度選代表。

### 3.3 Ollama（視覺語意，預設掛接方式）

程式預設連本機：

`http://127.0.0.1:11434`

你只要讓服務在跑、模型已下載，**不必在本專案再填設定檔**。

**安裝與掛接步驟：**

1. 到 [ollama.com](https://ollama.com/) 安裝（Windows 有安裝程式；Linux 用官網一鍵腳本）。
2. 開終端機下載模型（約數 GB，需顯存足夠，建議 ≥12GB）：

```powershell
ollama pull qwen2.5vl:7b
```

3. 確認服務有在聽（安裝後通常會自動常駐）：

```powershell
ollama list
# 或瀏覽器 / curl 打 http://127.0.0.1:11434
```

4. 開本程式視窗 →「Ollama」檢查應顯示模型可用。勾「視覺語意」，模式選 `fast`（預設）即可。

**和顯卡的關係：** Ollama 自己用 GPU 跑 VLM；本程式的美學分會**先跑完並釋放顯存**，再呼叫 Ollama，減少兩套模型搶記憶體。兩邊共用同一張卡，但不共用同一個 Python 行程。

Ollama 沒開或沒模型 → 檢查變黃；語意分析略過，清晰度／連拍／美學仍可整理。

### 3.4 改用 vLLM（進階，可選）

若你自己起了 OpenAI 相容的 vLLM：

```powershell
py -3.11 -m photocull run --input "..." --output "..." --vlm-base-url http://127.0.0.1:8000 --vlm-model 你的模型名
```

程式改打 `{base}/v1/chat/completions`，不再連 Ollama。視窗目前預設走 Ollama；進階網址請用指令列。

### 3.5 ExifTool（RAW 建議）

| | |
| --- | --- |
| 作用 | 讀 RAW 拍攝時間、抽內嵌預覽（不解完整 RAW） |
| 掛接 | 只要 `exiftool` 在系統 PATH，程式用子行程呼叫 |
| Windows | 從 [exiftool.org](https://exiftool.org/) 安裝，並讓終端機打得到 `exiftool` |
| Linux | 例如 `sudo apt install exiftool` |

沒裝 → JPEG 不受影響；RAW 若抽不到預覽會進覆核。

### 3.6 還要裝什麼（本專案本身）

兩邊都需要：

1. **Python 3.11+**
2. 本專案：`pip install -e .`；要用美學分再 `pip install -e ".[gpu]"`
3. 上一節的驅動／PyTorch／Ollama／權重／ExifTool

### 3.7 Windows 一鍵啟動前檢查清單

```powershell
cd "專案目錄"
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e .
pip install -e ".[gpu]"
# 若 cuda 為 False：依 PyTorch 官網重裝 CUDA 版 torch
ollama pull qwen2.5vl:7b
```

確認 `models\sac+logos+ava1-l14-linearMSE.pth` 存在後：

```powershell
.\scripts\windows_gui.ps1
# 或雙擊 照片整理.exe
```

照片與結果請放在 **NTFS**。exFAT 不能建硬連結。

### 3.8 Linux 檢查清單

```bash
cd "專案目錄"
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e .
pip install -e ".[gpu]"
# 依官網安裝對應 CUDA 的 torch
ollama pull qwen2.5vl:7b
# 建議：sudo apt install zenity fonts-noto-cjk exiftool

./scripts/linux_launch.sh
```

照片與結果請放在 **ext4 / XFS / Btrfs**。驅動、CUDA、Ollama 都要用 Linux 版；不能從 Windows 直接搬。

## 4. 操作方法

### 4.1 視窗（建議日常使用）

1. 開啟視窗（見上一節）。
2. 上方會檢查記憶體、顯示卡、Ollama、美學權重、ExifTool。
3. **新增資料夾**：一次一組。結果預設同磁碟、名稱結尾 `_整理`。
4. **批次加入**：一次連選多個。Windows 用系統連選；Linux 優先 zenity，沒有則先選上層再連選子資料夾。
5. 勾選要開的篩選；可調連拍秒數、清晰度、美學門檻、休息分鐘數（填 0 表示不休息）。
6. **開始整理** → 確認視窗 → 依序處理。一次只跑一個資料夾。
7. 跑完看「結果標示」與下方彩色摘要。可用按鈕開啟保留、覆核、廢片。

原檔只會被讀取。關閉視窗若正在整理，會中斷當前這一批。

### 4.2 指令列

Windows：

```powershell
py -3.11 -m photocull run --input "D:\照片樣本" --output "D:\照片樣本_整理" --vlm fast
py -3.11 -m photocull report --output "D:\照片樣本_整理"
```

Linux：

```bash
python -m photocull run --input "/照片/樣本" --output "/照片/樣本_整理" --vlm fast
python -m photocull report --output "/照片/樣本_整理"
```

常用參數：

| 參數 | 說明 |
| --- | --- |
| `--vlm fast` | 只看準備留下的與連拍矛盾少數張（視窗預設） |
| `--vlm off` | 關閉視覺語意，最快 |
| `--vlm auto` | 另含散張灰帶 |
| `--vlm all` | 通過快篩的都看 |
| `--no-sharpness` / `--no-burst` / `--no-aesthetic` | 關閉對應篩選 |
| `--burst-gap` | 連拍秒數，預設 2 |
| `--blur-floor` / `--sharp-ok` | 清晰度地板與過關線，預設 20 / 80 |
| `--aes-drop` / `--aes-keep` | 美學偏低與保留線，預設 4.2 / 6.0 |
| `--strict-aesthetic` | 技術過關但美學很低的散張直接進美學廢片 |

### 4.3 第一次請用複本

不要第一次就對正式照片庫試。複製幾十張到同磁碟另一個資料夾，結果也放同磁碟、不要放在輸入資料夾裡面。

### 4.4 重跑

`catalog.sqlite` 還在時，預覽雜湊沒變的分數與視覺結果會沿用。要整批重算分數，刪掉該結果資料夾裡的 `catalog.sqlite` 再跑；不會動到原檔。

## 5. 兩邊差異摘要

| 項目 | Windows | Linux |
| --- | --- | --- |
| 整理演算法 | 相同 | 相同 |
| 視窗 | `gui` / `照片整理.exe` | `gui` / `linux_launch.sh` |
| 批次連選 | 系統 COM 對話框 | zenity，或上層＋清單 |
| 開啟結果資料夾 | `os.startfile` | `xdg-open` |
| 硬連結檔案系統 | NTFS、ReFS | ext4、XFS、Btrfs、ZFS |
| 雙擊執行檔 | 有 `照片整理.exe` | 無；用腳本或指令 |

## 6. 常見狀況

**硬連結全部失敗**  
多半是 exFAT，或結果與原檔不在同一磁碟。改放 NTFS / ext4 同碟再跑。

**視覺語意很慢**  
預設已改成 `fast`。再快可關視覺語意，只留清晰度與美學分。

**Ollama 沒開**  
檢查會標注意；視覺語意會略過，其餘整理仍會完成。

**Linux 中文變方框**  
安裝 `fonts-noto-cjk` 這類中文字型後重開視窗。

**沒有 zenity**  
批次加入會改成「先選上層，再連選子資料夾」。一次加一個資料夾不受影響。
